# Задание для основного Codex / Sol

Реализуй **только read-only v0.1** проекта jiractl по этому пакету. Цель: context-efficient CLI + Skill для self-hosted Jira/PAT; mcp-atlassian — pinned coverage/behavior reference, не runtime dependency.

Сначала прочитай README.md, AGENTS.md и релевантные разделы docs/PRD.md, docs/CLI-CONTRACT.md, docs/ADR.md, docs/IMPLEMENTATION-PLAN.md. Проверь внутренние противоречия; разреши их небольшой явной contract patch до параллельной реализации. Не начинай с полного переписывания документов. Принятый стек Go 1.27.1, Cobra v1.10.2, Viper v1.21.0; зависимости закреплены в go.mod/go.sum. Bootstrap version/config уже создан, продуктовые команды ещё planned.

Используй planning/tasks.json, T00–T08. Не строй отдельный workflow engine. T09–T12 и E-серию не реализовывай в этом задании. Не выполняй никаких Jira mutations, даже через временные scripts. Для разрешённого read-only тестирования можно использовать уже существующие `JIRA_*` environment variables, но не выводить значения, не сохранять их или production payloads в prompts/repository/logs/fixtures и не угадывать exact names, aliases или endpoints. Это не реализует bootstrap support `JIRA_*`: текущий bootstrap использует `JIRACTL_*`. PAT уже должен быть настроен безопасно в окружении; не проси вставлять его в prompt и не выводи значение.

Ты — integrator/contract owner. Делегируй только whole bounded tasks: routine_worker — Luna/low для детерминированных checks, кратких логов, точных механических правок и явно разрешённого commit; documentation_writer — Terra/medium для docs; Sol implementer делает bounded vertical slices, Sol reviewer — независимый review, Luna researcher — source inventory, Luna fixture_writer — механические fixtures по frozen schema. Общий default остаётся Terra/medium. Модели и effort задаются явно в `.codex/agents`; при недоступности named role не меняй модель/approval policy/sandbox молча.

Go-инструменты полного pack validation и upstream inventory отложены в T-TOOLING; не объявляй их выполненными. Начни с T00: pinned checkout и статусы static/runtime inventory, версия/особенности target deployment, состояние окружения. Coverage seed не является полным инвентарём. Не выдумывай IDs или endpoints. При отсутствии live Jira продолжай offline на синтетических fixtures, отдельно отметь target verification gap. Не объявляй verified поддержку production без проверки.

В T01 заморозь contracts и shared DTO. Затем допускается T02/T03/T04 параллельно с disjoint ownership, не более трёх активных субагентов и без рекурсивного делегирования. Дай каждому одну задачу с целью, конкретной cwd/worktree, allowed paths, только нужными sources и acceptance commands; для named override создай fresh session. Проверь, что ваш клиент действительно соблюдает выбранную cwd; иначе один writer для пересекающихся paths и parallel read-only work.

После T02/T03 быстро получи `issue get` end-to-end, затем search/sections, затем snapshot 100/resume/diff. В batch нет вызовов модели. Не создавай новую LLM-сессию на каждый issue, HTTP page или исправление теста. Существующему worker давай точный repro; максимум два correction rounds, затем решай границу задачи сам. Повторяй checks только после изменения или при недостаточном evidence.

Перед acceptance требуй `contracts/handoff.schema.json` только для planned product task с `Txx`/`Exx` и существующим base commit. Для routine/docs/smoke требуй компактный отчёт: changed files, выполненные команды/exit codes, evidence paths и gaps — без выдуманных ID или SHA. Tests/evidence должны относиться к commit, когда commit существует. Требуй актуальное evidence для integration head; checks запускай повторно только после последующего изменения либо при недостаточном evidence, затем ставь accepted. Stale handoffs исправляй одной ограниченной reconciliation round, а не перезапуском всего графа.

Приёмка: валидный bounded JSON; lossless spill/targeted artifact read; правильные pagination/null/completeness/namespace; no secret leakage; read-only dispatch; deterministic 100-issue capture с fault-injection/resume; honest tuned-MCP benchmark; clean package install. Runtime Skill устанавливай только после появления CLI. Не рекламируй planned commands как реализованные.

Финальный отчёт: что реализовано, где files/commits/tests/evidence, реальные метрики, список неисполненных live проверок, известные ограничения, verdict v0.1. Не выдавай scaffolding или одни mocks за завершённый продукт. После T08 остановись.
